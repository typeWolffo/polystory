# .polystory/

Two files the scripts read, one the modeller reads, and generated state.

```
.polystory/
  profile.json      facts: kinds, folders, units, budgets, slots, rig, registration
  style.json        the look the build applies: knobs and the palette
  style.md          the look in words, read before every recipe
  scan.json         generated by `polystory scan`, git-ignored
  previews/         generated by `polystory preview`, git-ignored
  calibration/      generated by `polystory calibrate`, git-ignored
  .glb-check-stamp  the hook's last look, git-ignored
```

Paths are relative to the project root; `~/` is allowed for files outside
it. The nearest `.polystory/` above the
working directory is the project; `--project <root>` or `POLYSTORY_PROJECT`
override.

## profile.json

```json
{
  "schemaVersion": 1,
  "blender": "auto",
  "kinds": {
    "<kind>": {
      "description": "one line: what this kind is for",
      "models": "path/to/models",
      "recipes": "path/to/recipes",
      "unitsPerMetre": 1,
      "slots": {
        "<slot>": { "folder": "hats", "socket": "socket_hat", "envelope": { "zMin": -0.1, "zMax": 0.9, "radiusMax": 0.75 } }
      },
      "budget": { "trisTarget": 4000, "trisMax": 8000, "bytesMax": 300000 },
      "skinnedBudget": { "trisTarget": 7500, "trisMax": 9000, "bytesMax": 300000 },
      "envelope": { "extentMax": 1.0, "centreMax": 0.15 },
      "rig": { "glb": "path/to/rig.glb", "unitsPerMetre": 1.654, "clip": "idle", "clipAt": 0.4 },
      "preview": { "mount": "socket", "socket": "socket_hand_R", "offset": [-0.5, -0.3, 0.2], "farMetres": 7, "scaleFigure": true },
      "ignore": ["rig*", "set*"],
      "register": { "command": "bun scripts/add-item.ts {id} {slot} {model} --name \"{name}\"", "doc": "what to run or edit after a build" }
    }
  }
}
```

- `blender`: optional, only for `polystory open` and `export --fbx`.
  `"auto"` looks on PATH and in the usual places; `POLYSTORY_BLENDER`
  wins over both.
- `kinds`: one entry per folder of models. A kind is a lower-case word.
- `models`, `recipes`: `models/<model>.glb` is built from
  `recipes/<model>.ts`; the paths mirror. A model with no recipe is
  hand-made and gets warnings where a recipe-built one gets errors.
- `unitsPerMetre`: how many recipe units make a metre. `1` for metres;
  a rig's `height in units / height in metres` for items in rig space.
- `slots`: only for a kind whose files sit in sub-folders by mounting
  point. `folder` is the sub-folder, `socket` the rig object the preview
  mounts on, `envelope` the bounds the check warns outside of, in the
  recipe's frame: `xMin/xMax/yMin/yMax/zMin/zMax`, `xAbsMax/yAbsMax/zAbsMax`,
  `radiusMax` (in x and y). A kind without slots has one flat folder and
  may carry `envelope` with `extentMax` (largest dimension) and
  `centreMax` (how far the bounds' centre may sit from the origin, which
  is the pivot).
- `budget`: `trisTarget` warns, `trisMax` and `bytesMax` fail.
  `skinnedBudget` is the same for files that carry a skin; without it a
  skinned file fails the check.
- `rig`: for previews and skinned checks. `glb` is the rig as the game
  loads it, with its sockets as named nodes; the preview mounts the item
  on them, and a skinned file must use its joints. `unitsPerMetre` is the
  rig's scale (defaults to the kind's). `clip` names an animation in the
  file to pose the rig with (default: `idle` when the file has one, else
  the bind pose) and `clipAt` the second of it to freeze at, so renders
  show the character as the game does, not in a T-pose.
- `preview.mount`: `socket` hangs the item under its slot's socket;
  `beside` floats it at `socket` + `offset` (rig units) as a prop about
  to be thrown; `turntable` stands it on a checker floor (0.1 m cells),
  with a 1.75 m figure beside it when `scaleFigure` is true. `farMetres`
  is the game's viewing distance, the `far` render.
- `ignore`: globs of files in `models` the check and the hook leave alone
  (the rig, the set, anything not built by a recipe and not meant to be).
- `register`: `command` runs after a build with `{field}` placeholders
  filled from the recipe's ITEM (`{file}` is the GLB's project-relative
  path); `doc` is the paragraph a person or the skill follows. Either or
  both; neither when the game loads files by name.

## style.json

```json
{
  "schemaVersion": 1,
  "direction": "toy",
  "knobs": { "bevel": 0.02, "bevelSegments": 2, "segments": 32, "sphere": [24, 12], "smooth": true, "smoothAngle": 45, "minThickness": 0.025, "materialsPerItem": 3 },
  "perKind": { "stage": { "materialsPerItem": 4 } },
  "materials": {
    "ink": { "hex": "#29004F", "roughness": 0.85, "role": "dark mass, frames, handles" },
    "glow": { "hex": "#67E1C9", "roughness": 0.6, "emissive": 1.0, "role": "anything that emits light" },
    "steel": { "hex": "#C9CDD6", "roughness": 0.35, "metallic": 0.8, "role": "brushed metal" }
  },
  "calibration": { "base": "ink", "accent": "glow", "dark": "ink", "light": "steel", "glow": "glow" }
}
```

- `knobs`: the kit's defaults, in the recipe's units. `bevel` width and
  `bevelSegments` on every hard edge (0 for none); `segments` around a
  cylinder, cone or torus; `sphere` [u, v]; `smooth` false means flat
  shaded; `smoothAngle` marks edges sharper than it; `minThickness` is
  the thinnest part that still reads, for the modeller; `materialsPerItem`
  warns above it.
- `perKind`: knob overrides for one kind (a kind in metres next to one in
  rig units needs a different bevel width).
- `materials`: the palette. `hex` is sRGB, exported linear; `roughness`
  0..1; `emissive` is the emission strength when the material glows;
  `metallic` 0..1, default 0. The check fails a file whose material name
  or colour is not here.
- `calibration`: which materials play the five roles in the calibration
  set, so `polystory calibrate style` can render the project's own look.
  Not needed when the palette already has `base`, `accent`, `dark`,
  `light` and `glow`.
